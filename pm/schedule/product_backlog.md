# Product Backlog — Danh sách User Story (AI-WMS)

**Phương pháp quản lý:** Agile / Scrum (Kích thước Story tiêu chuẩn 24h - 36h làm việc tổng hợp BA - Dev - Test)

Tài liệu này đặc tả toàn bộ các chức năng thuộc hệ thống **Kho Thông Minh (Viettel AIWS)** thành danh sách User Story tinh gọn, bao gồm **phân tách trọn bộ User Story tác nghiệp hiện trường End-to-End chuyên biệt** cho 3 Phân hệ tác nghiệp cốt lõi: **Nhập kho (MM.10A - MM.10G)**, **Xuất kho (MM.11A - MM.11G & Xuất VC)** và **Chuyển kho / Điều chuyển STO (MM.12 & MM.13A - MM.13C)**.

**Quy chuẩn Tách User Story (Right-Sizing & Capacity Standards):**
- **Chuẩn thời gian làm việc:** Mỗi User Story được phân tách với quy mô tối đa từ **2 SP đến 3 SP**, tương đương **24h đến 36h làm việc tổng hợp** (bao gồm phân tích BA, phát triển Dev và kiểm thử Test). Không có User Story nào vượt quá 3 SP.
- **Tính đồng bộ Web/Mobile (`[Web/Mobile]`):** Tất cả các chức năng tác nghiệp, tra cứu, xem chi tiết lệnh (đầy đủ 6 Tab: Hàng hóa, Chứng từ, Task, KCS/Đánh giá, Vận chuyển, Lịch sử), tìm kiếm nhanh/nâng cao, xác nhận đơn nhập/xuất/chuyển kho, quản lý task, duyệt giao việc, PDF chứng từ, trình ký VOffice, vận chuyển, dashboard và thông tin cá nhân **đều hỗ trợ trên cả Web và Mobile**.
- **Chức năng System / Web Special:** 
  - `[System]`: Tiến trình tự động nền (Đồng bộ SAP, tự động phân việc, tự động sinh Task Picking, đề xuất tải trọng xe).
  - `[Web]`: Công cụ cấu hình admin chuyên sâu, bộ vẽ mặt bằng *2D Visual Canvas Layout Editor*, phân quyền tài khoản Admin, xuất file Excel dung lượng lớn.

Hệ thống sử dụng cơ chế xác thực tập trung **Viettel SSO (Single Sign-On)**.

## 4. Quy tắc gán Story Point & Độ ưu tiên

*   **Độ ưu tiên (Priority):**
    *   **High:** Các chức năng nền tảng thiết yếu, luồng nghiệp vụ cốt lõi hoặc thao tác hiện trường bắt buộc (Đăng ký xe, thêm công cụ, phân quyền, đồng bộ SAP, luồng nhập/xuất/chuyển kho, claim task, quét RFID/Barcode).
    *   **Medium:** Các chức năng quản lý mở rộng, soát xét, quy hoạch slotting, dashboard chi tiết và tối ưu hóa vận hành.
    *   **Low:** Các báo cáo thống kê phụ, tùy biến giao diện cá nhân hoặc thông tin lịch sử tra cứu mở rộng.
*   **Story Point (Quy đổi chuẩn 24h - 36h làm việc):**
    *   **2 SP:** Tương đương **24h làm việc tổng hợp (BA + Dev + Test)**. Áp dụng cho các trang tra cứu danh sách, bộ lọc, xem hồ sơ, render template hoặc thao tác ghi nhận đơn giản.
    *   **3 SP:** Tương đương **36h làm việc tổng hợp (BA + Dev + Test)**. Áp dụng cho các nghiệp vụ tác nghiệp phức tạp hơn như gán mã RFID, xử lý luồng quy trình, quét barcode xác nhận, hoặc tích hợp API trao đổi dữ liệu.
    *   *Lưu ý:* **Không có User Story nào vượt quá 3 SP** (loại bỏ hoàn toàn mức 5 SP để đảm bảo tính tinh gọn theo chuẩn Agile Sprint).
